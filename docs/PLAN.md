# PDF 용량 줄이기 웹앱 기획서

> 원본은 Claude Docs 문서 "PDF 용량 줄이기 웹앱 기획서"이고, 이 파일은 **2026-10-28 기준 사본**이다. 단계가 끝날 때 [HANDOFF.md](./HANDOFF.md)와 함께 갱신한다. 진행 상황은 HANDOFF.md가 우선한다.

## 1. 인터뷰 결과와 결정 사항

PDF를 서버로 올리지 않고 **사용자 브라우저 안에서** 압축하는 정적 웹앱으로 만든다. 이 결정으로 Vercel의 요청 크기 제한(서버 함수 약 4.5MB)과 서버 비용 문제가 사라진다.

| 질문 | 답변 | 설계에 미치는 영향 |
| --- | --- | --- |
| 처리 위치 | 브라우저에서 처리 | 서버 없음. WebAssembly(WASM) PDF 엔진을 Web Worker에서 실행 |
| 사용 범위 | 외부 공개, 파일 100MB 이하 | 메모리·진행률·취소 기능 필수. 공개 서비스라 라이선스와 Vercel 약관 확인 필요 |
| 압축 방식 | 이미지만 줄이고 글자 유지 | 텍스트·벡터·글꼴은 그대로, 이미지 해상도(DPI)와 JPEG 품질만 낮춤 |
| 예상 사용량 | Claude 사용량(토큰) | 8장에 개발 단계별 토큰 추정 |

## 2. 목표·범위·제약

목표는 **100MB 이하 PDF를 올리고, 줄일 비율을 고르고, 글자는 그대로인 작은 PDF를 내려받는 것**까지 3단계 안에 끝내는 것이다.

**범위에 포함**

- PDF 1개씩 업로드(드래그 앤 드롭·파일 선택), 압축, 다운로드
- 목표 감소율 선택과 고급 옵션 5종(3장)
- 원본·결과 크기 비교, 진행률, 취소
- PC 브라우저(Chrome·Edge·Firefox·Safari 최신판)와 모바일 브라우저

**범위에서 제외(1차)**

- 여러 파일 일괄 처리, 회원 가입·로그인, 서버 저장
- 페이지 전체를 이미지로 바꾸는 강제 압축, 암호 걸린 PDF 해제
- PDF/A 등 규격 변환, OCR

**제약**

- 파일은 사용자 PC 메모리에서 처리한다. 100MB 파일은 처리 중 메모리를 약 3~5배(300~500MB) 쓰므로 저사양 모바일에서는 실패할 수 있다. 이때 안내 문구를 띄운다.
- 이미지가 거의 없는 PDF(문서 원본 내보내기)는 목표 비율까지 줄지 않을 수 있다. 글자 유지를 택했기 때문이며, 결과 화면에서 "이 이상 줄이려면 글자 품질도 낮춰야 합니다"라고 알린다.
- 결과가 원본보다 커지면 원본을 그대로 돌려준다.

## 3. 기능 명세

사용자는 "원본보다 몇 % 줄일지"만 고르고, 프로그램이 그 목표에 맞는 **가장 덜 손상되는 이미지 품질**을 자동으로 찾는다.

### 3.1 목표 감소율

- 선택: 빠른 버튼 25% · 50% · 75% + 슬라이더 10~90%(5% 단위). 기본값 50%.
- 목표 크기 = 원본 × (1 − 감소율). 예: 20MB, 50% → 10MB 이하.
- 품질 단계표(아래)를 이진 탐색으로 시도해, 목표를 만족하는 가장 약한 단계를 고른다. 단계가 6개라 최대 3~4회만 다시 압축한다.
- 가장 강한 단계로도 목표에 못 미치면 그 결과를 주고 "목표 50%, 실제 32% 감소"처럼 실제 값을 보여준다.

| 단계 | 이미지 해상도 상한 | JPEG 품질 | 용도 |
| --- | --- | --- | --- |
| 1 | 200 DPI | 85 | 인쇄용에 가까운 품질 |
| 2 | 150 DPI | 75 | 일반 문서 |
| 3 | 120 DPI | 65 | 화면 보기 |
| 4 | 96 DPI | 55 | 메일 첨부 |
| 5 | 72 DPI | 45 | 최소 용량 |
| 6 | 60 DPI | 35 | 극한 압축 |

수치는 개발 초기 시험(7장 T-05)으로 조정한다.

### 3.2 고급 옵션

| 옵션 | 기본값 | 하는 일 | 구현 난이도 |
| --- | --- | --- | --- |
| 미사용 리소스 제거 | 켬 | 어느 페이지에서도 쓰지 않는 글꼴·이미지·객체를 버림 | 낮음 |
| 문서 구조 압축 | 켬 | 객체를 묶어(객체 스트림) 압축하고 스트림을 다시 압축 | 낮음 |
| 중복 객체 제거 | 켬 | 똑같은 이미지·글꼴이 여러 번 들어 있으면 하나로 합침 | 낮음 |
| 메타데이터 제거 | 끔 | 작성자·제목·XMP 등 문서 정보 삭제 | 낮음 |
| 페이지 썸네일 제거 | 켬 | 페이지마다 들어 있는 미리보기 이미지(Thumb) 삭제 | 낮음 |

다섯 가지 모두 엔진의 저장 옵션이나 객체 몇 개 삭제로 해결되어 복잡하지 않으므로 1차에 모두 넣는다. 메타데이터는 문서 제목이 사라지는 부작용이 있어 기본값을 끔으로 둔다.

### 3.3 결과 화면

- 원본 크기 → 결과 크기, 실제 감소율, 적용 단계, 처리 시간
- 다운로드 파일명: `원본이름_compressed.pdf`
- "다시 압축"(설정만 바꿔 같은 파일로 재시도)

### 3.4 예외 처리

| 상황 | 동작 |
| --- | --- |
| PDF가 아닌 파일, 100MB 초과 | 업로드 단계에서 거부 + 안내 |
| 암호 걸린 PDF | "암호가 걸린 PDF는 지원하지 않습니다" |
| 손상된 PDF | 엔진이 복구를 시도, 실패 시 오류 안내 |
| 결과가 원본보다 큼 | 원본 유지 + "이미 최적화된 파일입니다" |
| 메모리 부족 | 처리 중단 + "PC 브라우저나 더 작은 파일로 시도" 안내 |

## 4. 기술 구조·스택·라이선스

압축 엔진은 Artifex의 공식 MuPDF.js(npm `mupdf`)를 Web Worker에서 돌린다. 이미지 재압축, 미사용 객체 정리, 중복 제거, 구조 압축을 한 엔진으로 처리할 수 있고, 화면은 처리 중에도 멈추지 않는다.

```
 GitHub 저장소 ──push·PR──▶ GitHub Actions ──배포──▶ Vercel (정적 배포)
                                                         │
                                       화면 파일과 엔진(WASM)만 내려받음
                                                         ▼
 ┌─ 사용자 브라우저 ──────────────────────────────────────────────────┐
 │                                                                      │
 │  원본 PDF ──▶ 화면 (React) ──▶ Worker + MuPDF ──▶ 압축 PDF           │
 │  최대 100MB   목표 %·옵션·진행률   이미지 재압축·정리   다운로드        │
 │                                                                      │
 │  파일 데이터는 서버로 전송하지 않음 (T-11에서 확인)                    │
 └──────────────────────────────────────────────────────────────────────┘
```

| 구분 | 선택 | 이유 |
| --- | --- | --- |
| 화면 | Vite + React + TypeScript | 정적 파일로 빌드되어 Vercel에 그대로 올라감 |
| 스타일 | Tailwind CSS | 화면 수가 적어 빠르게 구성 |
| PDF 엔진 | MuPDF.js (WebAssembly) | 브라우저에서 이미지 재압축·`garbage`·`compress` 저장 옵션 제공 |
| 백그라운드 처리 | Web Worker + Comlink | 100MB 처리 중에도 화면 응답 유지, 취소 가능 |
| 단위 테스트 | Vitest | 설정 계산·검증 로직 |
| 화면 테스트 | Playwright | 실제 브라우저에서 업로드→압축→다운로드 확인 |
| 소스 관리·CI | GitHub + GitHub Actions | PR마다 빌드·테스트 |
| 배포 | Vercel (Git 연동) | main 병합 시 자동 배포, PR마다 미리보기 주소 |

**옵션별 엔진 처리**

| 옵션 | MuPDF 처리 |
| --- | --- |
| 이미지 품질 단계 | 이미지 다시 쓰기(해상도 상한 + JPEG 품질). 공개 API에 없으면 이미지 객체를 하나씩 꺼내 줄인 뒤 JPEG로 바꿔 넣는 방식으로 직접 구현 |
| 미사용 리소스 제거 | 저장 옵션 `garbage` + `clean` |
| 중복 객체 제거 | 저장 옵션 `garbage=deduplicate` |
| 문서 구조 압축 | 저장 옵션 `compress`(+ 지원 시 객체 스트림) |
| 메타데이터 제거 | 문서 정보(Info)와 XMP(Metadata) 항목 삭제 |
| 썸네일 제거 | 각 페이지의 Thumb 항목 삭제 |

**T-01 결과(2026-10-28)**: MuPDF.js 1.28.1에는 이미지 다시 쓰기 API가 없어 직접 구현 경로로 만들었다(이미지를 꺼내 축소 → JPEG → 스트림 교체). 저장 옵션에 객체 스트림도 없어 `compress` + `garbage=4`를 쓴다. 자세한 내용과 주의점은 [HANDOFF.md](./HANDOFF.md) 6-1.

**라이선스**

MuPDF.js는 **AGPL-3.0** 또는 유료 상용 라이선스다. 외부에 공개하는 웹서비스에 쓰면 이 앱의 소스도 AGPL로 공개해야 한다. 그래서 다음과 같이 운영한다(2026-10-28 확정).

- GitHub 저장소를 공개(public)로 두고 `LICENSE`를 AGPL-3.0으로 한다.
- 화면 아래에 "소스 코드" 링크(GitHub)를 둔다.

저장소를 비공개로 하려면 상용 라이선스를 사거나, 엔진을 pdf-lib(MIT) + 브라우저 Canvas 재압축으로 바꿔야 한다. 이 경우 중복 제거·미사용 리소스 정리를 직접 구현해야 해 개발량이 약 1.5배가 된다.

참고: [MuPDF.js npm](https://www.npmjs.com/package/mupdf) · [MuPDF 이미지 다시 쓰기 API](https://mupdf.readthedocs.io/en/1.28.0/_static/generated/c/html/image-rewriter_8h.html)

## 5. 화면 설계

화면은 한 페이지이고, 상태에 따라 아래 4단계로 바뀐다. 한국어를 기본으로 하고 문구는 한 파일(`src/strings.ts`)에 모아 나중에 영어를 추가할 수 있게 한다.

1. **업로드** — 큰 드롭 영역 + "PDF 선택" 버튼, "파일은 서버로 전송되지 않고 내 브라우저에서만 처리됩니다" 문구, 최대 100MB 안내
2. **설정** — 파일 이름·크기·페이지 수, 목표 감소율(25/50/75% 버튼 + 슬라이더, 예상 목표 크기 표시), "고급 옵션" 접이식 영역에 체크박스 5개, [압축 시작]
3. **처리 중** — 진행 막대와 현재 작업("이미지 다시 압축 중 3/6단계"), [취소]
4. **결과** — 원본 → 결과 크기와 감소율, 적용 단계, [다운로드] [다른 설정으로 다시] [새 파일]

공통: 화면 아래에 개인정보 안내(서버 저장 없음), 소스 코드 링크, 버전. 모바일 폭(360px)에서도 한 열로 깨지지 않게 한다.

## 6. GitHub·Vercel 운영

`main` 브랜치에 병합되면 Vercel이 자동으로 운영 배포하고, PR마다 미리보기 주소가 생긴다. 서버 코드가 없어 Vercel은 정적 파일만 내려준다.

| 항목 | 내용 |
| --- | --- |
| 저장소 | https://github.com/doit2/pdf-diet (공개, AGPL-3.0) |
| 운영 주소 | https://pdf-diet.vercel.app |
| 브랜치 | `main`(운영) ← `feature/*`(작업). PR로만 병합 |
| CI | GitHub Actions: 설치 → 타입 검사 → 단위 테스트 → 빌드 (→ 4단계에서 Playwright 화면 테스트 추가) |
| 배포 | Vercel 프로젝트 `pdf-diet`를 저장소에 연결. 빌드 명령 `npm run build`, 출력 폴더 `dist` |
| 캐시 | WASM·JS 파일은 이름에 해시를 붙여 1년 캐시. 재방문 시 엔진을 다시 받지 않음 |
| 보안 헤더 | `vercel.json`에 CSP(외부 전송 차단), `X-Content-Type-Options` 설정 |
| 버전 | `package.json` 버전 + Git 태그(`v1.0.0`), 화면 하단 표시 |

**Vercel 요금제**: 광고·유료 기능이 없으므로 무료 Hobby 요금제를 쓴다(Hobby는 개인·비상업용만 허용). 업로드가 서버를 거치지 않으므로 사용자 1명당 전송량은 화면 파일과 엔진(첫 방문 수 MB)뿐이라, Hobby의 월 100GB 전송 한도 안에서 수만 회 방문을 감당할 수 있다. 수익화하면 Pro로 전환한다.

참고: [Vercel Hobby 요금제](https://vercel.com/docs/plans/hobby) · [Vercel 공정 사용 지침](https://vercel.com/docs/limits/fair-use-policy)

## 7. 테스트 계획

테스트는 자동 3층(단위·엔진·화면)과 사람이 보는 수동 점검 1층으로 나누고, 자동 테스트는 PR마다 GitHub Actions에서 돈다. 합격 기준은 **글자가 그대로 선택·검색되고, 목표를 달성하거나 실제 감소율을 정확히 알려주는 것**이다.

### 7.1 테스트용 PDF 묶음

저작권 문제가 없도록 테스트 PDF는 스크립트로 직접 만든다(`tests/fixtures/make.ts`).

| 파일 | 특징 | 확인할 점 |
| --- | --- | --- |
| text-only.pdf | 글자만, 10쪽 | 거의 줄지 않음 → 안내 문구 |
| photo-heavy.pdf | 고해상도 사진 20장 | 목표 50%·75% 달성 |
| mixed.pdf | 글자 + 사진 + 표 | 글자 추출 결과가 원본과 같음 |
| duplicate-images.pdf | 같은 로고가 50쪽에 반복 | 중복 제거 효과 |
| with-thumbs-meta.pdf | 썸네일·메타데이터 포함 | 옵션 켜면 해당 항목이 사라짐 |
| scan-like.pdf | 흑백 스캔 이미지 | 흑백 이미지 깨짐 없음 |
| encrypted.pdf | 암호 걸림 | 거부 안내 |
| broken.pdf | 끝부분 잘림 | 오류 안내 또는 복구 |
| big-95mb.pdf | 95MB | 시간·메모리 기록, 화면 멈춤 없음 |

## 8. 개발 단계와 예상 Claude 사용량(토큰)

전체 개발에 약 100만 토큰(범위 70만~140만)을 예상한다. 대부분은 Claude가 코드·테스트 결과·이전 대화를 다시 읽는 입력 토큰이고, Claude가 새로 쓰는 출력 토큰은 그중 10~15%(약 10만~15만)다.

| 단계 | 산출물 | 대화 횟수 | 예상 토큰 | 상태 |
| --- | --- | --- | --- | --- |
| 0. 기획 | 이 기획서 | 1 | 8만 | 완료 |
| 1. 골격 | Vite+React 프로젝트, GitHub 저장소, Actions CI, Vercel 연결 | 1~2 | 10만 | 완료 (2026-10-28) |
| 2. 엔진 | Worker, 이미지 재압축, 옵션 5종, 목표 탐색, T-01·T-05 | 3~4 | 30만 | 진행 중 (T-05 남음) |
| 3. 화면 | 4단계 화면, 진행률·취소, 모바일 대응 | 2 | 15만 | 예정 |
| 4. 테스트 | 테스트 PDF 생성, 단위·엔진·화면 테스트 | 2~3 | 20만 | 예정 |
| 5. 배포·안정화 | 운영 배포, 수동 점검 반영, README·릴리스 | 2 | 15만 | 예정 |
| 합계 | | 11~14 | 약 98만 | |

**토큰을 늘리는 요인**: MuPDF 이미지 API가 브라우저 패키지에 없어 직접 구현할 때(+15만), 대용량 파일 메모리 문제 해결(+10만), 실제 브라우저에서 원인 찾기가 어려운 오류(+10만~20만).

**토큰을 아끼는 방법**: 단계마다 새 대화로 시작하고 [HANDOFF.md](./HANDOFF.md)로 이어받기, 테스트 로그는 실패한 부분만 붙여 넣기, 큰 PDF 파일 자체는 대화에 올리지 않기.
