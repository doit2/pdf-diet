# T-13 수동 점검표 (실제 기기)

운영 주소 https://pdf-diet.vercel.app 에서 직접 확인한다. 자동 테스트(T-04~T-12)는 CI에서 통과한 상태.
결과는 표의 "결과" 칸에 ✅ / ❌ + 메모로 적고, 모두 끝나면 v1.0.0 태그를 단다.

## 1. 준비할 PDF

- 사진이 많은 실제 PDF 1개 (카탈로그, 사진 보고서 등 10~50MB)
- 글자+표가 섞인 실제 업무 문서 1개 (스캔본이면 더 좋음)
- (선택) 50MB가 넘는 PDF 1개 — 휴대폰 한계 확인용

## 2. 기기별 확인

| # | 기기·브라우저 | 확인할 것 | 결과 |
| --- | --- | --- | --- |
| 1 | PC Chrome/Edge | 사진 PDF 50% → 다운로드 → Acrobat·브라우저로 열림, 글자 선택·검색 됨 | |
| 2 | PC Chrome/Edge | 업무 문서 75% → 글자·표가 원본과 같고 깨진 쪽 없음 | |
| 3 | Android Chrome | 사진 PDF 50% → 다운로드 → 기기에서 열림 | |
| 4 | iPhone Safari | 사진 PDF 50% → 다운로드(파일 앱에 저장) → 열림 | |
| 5 | 휴대폰 (가능하면) | 50MB 넘는 PDF: 끝까지 되는지, 실패하면 안내 문구가 나오는지. 설정 화면에 노란 메모리 안내가 보이는지 | |
| 6 | 아무 기기 | 처리 중 취소 → 설정 화면으로 돌아옴, 다시 압축 가능 | |

## 3. 화질 재확인 (단계 4~6)

실제 사진·스캔 PDF를 75%·90%로 줄여 결과 화면의 "이미지 품질 단계"를 확인하고 열어 본다.

| 단계 | 기준 | 결과 |
| --- | --- | --- |
| 4 (96DPI/55) | 사진: 화면에서 보기 괜찮음 / 스캔 글자: 읽힘 | |
| 5 (88DPI/50) | 스캔 숫자 혼동 없음 | |
| 6 (80DPI/45) | 9pt 숫자 판독 가능 | |

문제가 있으면 `src/engine/types.ts`의 LEVELS 하한을 올린다(2단계 T-05와 같은 방식).
